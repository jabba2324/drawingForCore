# What drawingForCore changed in lifted code and tests

drawingForCore runs Microsoft's own System.Drawing.Common rather than a reimplementation of it. Microsoft's source is
**lifted**: copied file by file from the upstream repository at a pinned commit, built for .NET 11, and tested with
Microsoft's own tests. This page explains the rules for those copies and what had to change.

- The full per-file list, with a link from each changed file to its upstream original, is generated:
  **[lifted-changes.md](lifted-changes.md)** (`tools/lift/changes_report.py`).
- The reasoning for every change is in [`LIFT.md`](../LIFT.md).
- Licences and attributions are in [`NOTICE`](../NOTICE) and [`LICENSE`](../LICENSE).

## Rules for lifted code

1. **Copy, don't rewrite.** Each file is copied byte for byte as it is upstream and keeps its copyright header.
2. **Every change is scripted and listed.** Changes are search-and-replace pairs (`FIXUPS`) in the lift scripts,
   `tools/lift/lift_drawing.py`, `lift_system_drawing.py` and `lift_drawing_tests.py`, plus the GDI+ import rewrite in
   `lift_drawing.py`. A pair
   that no longer matches upstream stops the lift. Each change carries a `// drawingForCore:` comment that gives the
   reason.
3. **Additions are kept separate.** Code drawingForCore wrote, the GDI+ engine, is in
   `tools/lift/additions/System.Drawing.Common/` and is copied in as new files (`SkiaGdiPlus/`).
4. **Every file is traceable.** `tools/lift/manifests/*.tsv` records each lifted file's upstream repository, commit and
   path.
5. **Identity is kept.** The assemblies keep Microsoft's names, versions and public keys (`keys/`, public signed), so
   existing references resolve to them. They aren't signed by Microsoft.
6. **Project files are generated** by the lift scripts. The lifted directories are output: change the script and lift
   again (`tools/lift/lift.sh`), rather than editing them. CI regenerates them on every run and fails on any
   difference.
7. **.NET Framework is the reference.** Where System.Drawing.Common on .NET behaves differently from System.Drawing on
   .NET Framework 4.8, a change restores 4.8's behaviour, and Windows GDI+'s output is what the engine aims for.

## Library changes, by kind

| Kind | Change | Where |
| --- | --- | --- |
| **GDI+ on SkiaSharp** | Every `[DllImport(LibraryName)]` of the GDI+ flat API (556 functions) becomes a method with the same signature that calls `SkiaGdiPlus`, the managed engine. It implements 516; the others are generated stubs that return GDI+'s NotImplemented status, which Microsoft's code turns into `NotImplementedException`. Calls on a `Graphics` whose HDC is out return ObjectBusy, as GDI+ does | `GdiplusNative.cs`, `GdiplusNative.Unix.cs` (generated by `lift_drawing.py`) |
| **No native GDI+ to load** | `LibraryResolver` no longer requires the `System.Drawing.EnableUnixSupport` switch (it still loads libcups for printing), and the GDI+ startup doesn't resolve libgdiplus | `LibraryResolver.cs`, `GdiplusNative.Unix.cs` |
| **.NET Framework behaviour** | `ImageFormatConverter` passes an unknown format name to `TypeConverter.ConvertFrom` (`NotSupportedException`), as .NET Framework did; .NET Core 3.0+ throws `FormatException`. Microsoft's System.Web.Helpers relies on the 4.8 behaviour | `ImageFormatConverter.cs` |
| **One definition of each type** | WebFormsForCore's System.Drawing defined its own `FontConverter`, `ToolboxBitmapAttribute` (a stub) and `BitmapSuffixInSatelliteAssemblyAttribute`, with their forwards commented out, and System.Drawing.Common defines them too: code that named one didn't compile (CS0433). Those three files aren't lifted, and the forwards are restored | System.Drawing's `AssemblyInfo.cs` (`lift_system_drawing.py`) |
| **Generated resources** | `SR.g.cs` is generated from `Strings.resx` (dotnet/runtime generates it at build time) | `lift_drawing.py` |

## Test changes, by kind

Tests change only to fit the platform. A failing test is never edited just to make it pass: either the engine is
fixed, or the failure is listed as known with its reason (`tools/ci/known-failures/`).

| Kind | Change |
| --- | --- |
| **GDI+ availability** | The suite's four "is GDI+ available" checks probe for libgdiplus and screen out old libgdiplus builds (by version, and on RedHat, Fedora and openSUSE). They answer for the managed engine instead |
| **Windows runs as Linux** | The suite's Windows checks (`PlatformDetection.IsWindows`, `[PlatformSpecific]`, two direct OS checks) mean "GDI+ is Windows' own", which it never is here. Windows answers as Linux and runs the same tests with the same expectations. The font-name test keeps its real OS check, since it depends on the fonts Windows installs |
| **Selection** | Microsoft's own categories: `category!=failing` and the non-Linux categories, as dotnet/runtime's Linux runs |
| **Test infrastructure** | arcade's Microsoft.DotNet.XUnitExtensions and RemoteExecutor are built from source (dotnet/runtime takes them from the dotnet-eng feed). xunit 2.4.1 and xunit.runner.visualstudio 2.4.5, the versions of the suite's time ([TESTING.md](TESTING.md)) |
