## drawingForCore 0.4.0

- **macOS:** tested on macOS 15 on Apple silicon (arm64) in CI, with the same tests and known failures as Linux and
  Windows, and a release waits for it (#13). The test host used to crash part-way through every macOS run. Two engine
  bugs caused it:
  - A Graphics whose image was disposed before it called into the image's freed bitmap when it flushed. On macOS
    `Graphics.Dispose` flushes, and `BufferedGraphics.Dispose` disposes its bitmap first, so disposing a
    `BufferedGraphics` could crash the process. On Linux, flushing after disposing the image crashed the same way.
  - `GetRegionScans` of a region as tall as GDI+'s infinite one (an infinite region less a rectangle, for example)
    rasterised 8,388,608 rows: two minutes on Linux, a crash on macOS. Tall regions are now rasterised in bands, in
    milliseconds, with the same rectangles.
- **Tests:** 6 new tests of drawingForCore's own (`Engine/MacOSCrashTests.cs`). The seven `RegionTests` Exclude/Xor
  theories that were left out of the Unix-disabled run for being slow now run (66 more cases), and
  `RegionTests.Complement_InfiniteRegion_Success` takes milliseconds instead of two minutes.
- **CI:** the Linux job's test step no longer ignores its failures (it had since the macOS diagnosis in 0.3.0).
- **Fonts on macOS:** families resolve through CoreText, and Arial, Times New Roman and Courier New are the real fonts,
  not Linux's metric-compatible substitutes; see README.md.

Known limitations: metafiles (EMF/WMF) aren't implemented, and Intel Macs aren't tested. See README.md.
