## drawingForCore 0.3.0

- **Packages:** `drawingForCore.Common` (System.Drawing.Common 11.0.0.0) and `drawingForCore` (System.Drawing 13.5.0.0),
  with the same assembly identities as 0.2.0. Drawing output is unchanged.
- **Engine and the code rules:** the GDI+ engine follows webForCore's code rules (#3). Pointers appear only in the flat
  API functions that receive GDI+'s data. Pixel buffers are spans, and the encoders no longer pin their arrays. 94 new
  tests of drawingForCore's own, recorded on the 0.2.0 engine, check that nothing changed (#16, #18).
- **More of Microsoft's tests:** CI now runs the tests Microsoft disabled on Unix as well (#12): 4,982 tests on Linux and
  4,995 on Windows. The main selection is 3,976 tests, 3,799 pass, 26 skipped and 151 known failures, on both
  platforms. A run whose test host crashes now fails.
- **macOS:** a CI job builds the packages on macOS (Apple silicon) and checks that they draw, save and reload PNG, JPEG
  and GIF. The test suite there is for information only: its test host crashes in CoreText's font metrics (#13).
- **Repository:** Microsoft's code comes from a submodule of xforcore's cleared-down fork, and the lift scripts are gone.
  The CI tools are C#, and the repositories, feed and downloads are under the xforcore organisation.

Known limitations: metafiles (EMF/WMF) aren't implemented, and macOS isn't supported yet. See README.md.
