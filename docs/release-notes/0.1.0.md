## drawingForCore 0.1.0

The first release of drawingForCore on its own. Until now it was part of
[webForCore](https://github.com/xforcore/webForCore) (up to webForCore 0.6.0, as the packages `webForCore.Drawing.Common`
and `webForCore.Drawing`). The code is the same; what's new is the packaging.

- **Packages:** `drawingForCore.Common` (System.Drawing.Common 11.0.0.0) and `drawingForCore` (System.Drawing 13.5.0.0,
  which depends on it). They replace `webForCore.Drawing.Common` and `webForCore.Drawing`.
- **A NuGet feed:** `https://xforcore.github.io/drawingForCore/index.json`. Add it as a package source; no account or
  token is needed.
- **Same identities:** the assemblies keep Microsoft's names, versions and public key tokens. They are now public
  signed with Microsoft's public keys (as dotnet/runtime's open-source builds are), where webForCore rewrote them after
  signing with its own key.
- **Fixed: `FontConverter` and two attributes were defined twice.** System.Drawing had its own copies of
  `FontConverter`, `ToolboxBitmapAttribute` and `BitmapSuffixInSatelliteAssemblyAttribute`, which System.Drawing.Common
  also defines, so code that named one of them didn't compile with webForCore's packages (CS0433). System.Drawing now
  forwards them to System.Drawing.Common, as it does every other GDI+ type.
- **Tests:** Microsoft's System.Drawing.Common 6.0 suite, 3,882 tests in CI on Linux and on Windows: 3,705 pass,
  26 skipped (10 of them need an installed printer), 151 known failures (141 are metafiles).

Known limitations: metafiles (EMF/WMF) aren't implemented, and macOS isn't tested. See README.md.
